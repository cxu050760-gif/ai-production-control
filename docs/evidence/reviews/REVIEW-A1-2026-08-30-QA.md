## 发现的缺陷

### DEF-A1（REWORK 主因）：单实例锁失效 — 持新鲜锁时 drive 不 SKIP_LOCKED
- **文件/行号**：`scripts/relay_autopilot.py` **L141-167**（`acquire_lock`），关键 L153 `if age is None or age < 0 or age > 300:` 分支内只处理 stale（删除重建）或异常（age=-1），**新鲜锁（0≤age≤300）不满足条件 → 不 return → 落到 L165 save_json 覆盖他人 lock.json + L167 return token**（视为抢锁成功）
- **复现**：手动创建 `autopilot/lock/lock.json`（token=fake、at=当前 UTC 新鲜）→ `python scripts/relay_autopilot.py drive --once` → **输出 `{"ok":true,"rounds":1}` 正常执行**（应输出 SKIP_LOCKED）；随后锁被覆盖/释放
- **影响**：README/实现者声称"并发调用第二个实例 SKIP_LOCKED"不成立——两个 drive 可并行修改 queue.json/run 目录，破坏 R 并发度=1 与队列一致性。当前 L2 无并发 drive 实际运行（计划任务不跑 autopilot），实际风险低，但属明确功能缺陷
- **修复建议**：L153 分支改为——`if age is not None and 0 <= age <= 300: return None`（新鲜锁→SKIP_LOCKED）；stale（age>300 或解析失败）才删锁重建；`else`（无 lock.json）分支保留删锁重建
- 回归验证：持锁时 drive 应输出 SKIP_LOCKED 且 lock.json 保持原 token；stale 锁（>300s）应自动回收并正常 drive

### OBS-A1（非缺陷，延迟 1 轮观察）
`advance_once` 的 `review_busy` 在 step1（REVIEWING→REWORK 释放门）**之前**快照，导致释放门的下一轮新 run 才准入（R3 实测 C 延迟 1 轮进门）。不破坏正确性（R4 正常进门），仅 1 轮空转；如需即时准入可在 step1 后重算 review_busy。
