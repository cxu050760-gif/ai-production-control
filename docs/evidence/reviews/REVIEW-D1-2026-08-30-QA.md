## 发现的缺陷

### DEF-D1（REWORK 主因）：litellm 依赖未就绪 + do_review 检查顺序问题
- **D1a — 依赖缺失**：README L31 声称"LiteLLM 1.83.0 已装"，但实测 Python 3.13 与 Python312 均无 `litellm`（`import litellm` 失败、`pip show litellm` 未找到）。后果：R-Adapter 测试 4 红（`test_review_mock_pass`/`test_review_mock_rework`/`test_review_mock_cli_exit_0`/`test_review_real_without_keys_returns_unconfigured`），`review --mode mock/real` 均返回 `LITELLM_NOT_INSTALLED`，"39/39 全绿"与"review mock 走通 LiteLLM Router"声称无法复现。
  - **修复建议**：安装 litellm（`pip install litellm`，README 已给镜像/代理指引）并确保可复现（建议在 pyproject.toml 登记依赖）；回归：装后 25/25 绿 + `review --mode mock --mock-verdict PASS/REWORK` 各 1 次实测返回正确 verdict。
- **D1b — 检查顺序**：`runtime/adapters/r_adapter.py` **L456-462** `do_review` 开头先 `from litellm import Router`（无 litellm → 直接返回 LITELLM_NOT_INSTALLED），在 **L490-497** real 模式的 keyed 检查之前。导致 `--mode real` 无 key 时返回 `LITELLM_NOT_INSTALLED` 而非预期的 `UNCONFIGURED`（测试 `test_review_real_without_keys_returns_unconfigured` 断言 `error == "UNCONFIGURED"` 失败）。
  - **修复建议**：把 litellm import 移到需要处——mock 分支在 `_build_router_mock` 前按需 import；real 分支先检查 `keyed`（无 key → 返回 UNCONFIGURED），有 key 才 import litellm。

### OBS-D1（非缺陷）
- 审核环境默认 `python` 为 workbuddy 自带 Python 3.13.14，而 README 指明 Python 3.12——两环境均无 litellm，故依赖缺失非解释器选择问题，是环境未装包。
- `worker_adapter.py` 对 stdin 协议仅支持"一次性输入 goal 后等待 stdout 结果"（subprocess.run input=goal），不支持交互式流式 worker；README 已注明"先确认各自 CLI 的 stdin 交互契约后再接入"（L3），可接受。
